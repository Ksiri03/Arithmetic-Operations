Aim

To write a Java program to perform addition, subtraction, multiplication and division, upload the source code to GitHub using Git, configure a Jenkins job to build and execute the program, create a Docker image, and deploy the application to Kubernetes.

4(a) Write the program and upload it to GitHub

The application is a small Java HTTP service with a browser calculator. The browser sends the two numbers to the Java API; the Java class performs the arithmetic and returns the result. The same program is then packaged and deployed in parts 4(b).

Step 3 — Write the arithmetic program

Calculator.java contains the four operations. BigDecimal is used instead of double so that decimal values are exact and division by zero can be rejected explicitly.

public static Result calculate(BigDecimal a, BigDecimal b, Operation operation) {
    BigDecimal value = switch (operation) {
        case ADD -> a.add(b);
        case SUBTRACT -> a.subtract(b);
        case MULTIPLY -> a.multiply(b);
        case DIVIDE -> {
            if (b.signum() == 0) {
                throw new ArithmeticException("Division by zero is undefined.");
            }
            yield a.divide(b, 10, RoundingMode.HALF_UP);
        }
    };
    return new Result(a, b, operation, value);
}

App.java starts a small HTTP server. The calculator page and the API use these routes:

Method and pathPurpose
GET /Serves the calculator page
GET /api/healthHealth check used by Kubernetes
GET /api/historyLast calculations for the current replica
GET /api/calculateCalculate from query parameters
POST /api/calculateCalculate from form parameters

4(b) Configure Jenkins, build the Docker image and deploy to Kubernetes

Jenkins clones the repository, compiles the Java sources, runs the tests, builds a versioned Docker image, loads the image into the local kind cluster, updates the Kubernetes Deployment and runs four live smoke checks.

Step 8 — Create the Dockerfile

Create a file named Dockerfile in the project root. The first stage compiles the program; the second stage contains only the Java runtime and the jar.

# syntax=docker/dockerfile:1
FROM eclipse-temurin:21-jdk-alpine AS build

WORKDIR /src
COPY src/main/java ./src/main/java
COPY src/main/resources ./src/main/resources

RUN find src/main/java -name '*.java' > sources.txt \
    && mkdir -p /out \
    && javac --release 17 -encoding UTF-8 -d /out @sources.txt \
    && cp -R src/main/resources/. /out/ \
    && jar --create --file /app.jar --main-class com.arithmetic.App -C /out .

FROM eclipse-temurin:21-jre-alpine

WORKDIR /app
COPY --from=build /app.jar /app/app.jar

ENV PORT=8080 \
    JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:+UseSerialGC -Djava.io.tmpdir=/tmp"

USER 10001:10001
EXPOSE 8080

ENTRYPOINT ["java", "-jar", "/app/app.jar"]

The runtime image runs as a non-root user. Kubernetes also starts it with a read-only root filesystem and a small in-memory volume for /tmp.

Troubleshooting note. One rehearsal build hit the first smoke-test health request because the NodePort briefly had no ready endpoint during the rolling update. The health request now retries for up to 48 seconds. The recorded build completed successfully. This is a normal Kubernetes rollout timing issue, not a calculation error.

Step 17 — Create the kind cluster and deploy

The Jenkins pipeline performs these Kubernetes commands automatically. They can also be run manually to create the cluster or recover the deployment:

Command 
> kind create cluster --name arithmetic-lab --config k8s\kind-config.yaml
> kind load docker-image arithmetic-ops:build-5 --name arithmetic-lab
> kubectl apply -k k8s
> kubectl -n arithmetic set image deployment/arithmetic-app app=arithmetic-ops:build-5
> kubectl -n arithmetic rollout status deployment/arithmetic-app
Output 
deployment.apps/arithmetic-app image updated
deployment "arithmetic-app" successfully rolled out

The Service is a NodePort on port 30081. The kind configuration maps host port 30081 to the control-plane container, so the application is available at http://localhost:30081.
